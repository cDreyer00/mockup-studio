# MCP

The daemon exposes an MCP server that does everything the editor does. An agent (Claude Code, Codex) creates, reads and edits documents through it, and the open editor reflects the changes in real time.

## How to connect

**stdio**, through the CLI (the CLI finds the daemon or starts a headless one):

```bash
mockup mcp
# or, without a global link:
node packages/cli/dist/bin.js mcp
```

Claude Code:

```bash
claude mcp add mockup-studio -- node <absolute-path>/packages/cli/dist/bin.js mcp
```

**Direct HTTP** (daemon running, `mockup serve` or `npm run dev`):

```
http://127.0.0.1:4747/mcp
```

```bash
claude mcp add --transport http mockup-studio http://127.0.0.1:4747/mcp
```

The transport is Streamable HTTP; sessions use the `mcp-session-id` header.

## Conventions

- Tool and parameter names are in `snake_case`.
- Responses are compact, designed to save agent context.
- Every write returns the tree summary at depth 2 (see below), so the agent can confirm the result without another read.
- `docId` is optional; when omitted, the active document is used (except in `close_document`, which requires it).
- Styles are real CSS in kebab-case (`"padding": "24px"`). Tokens are CSS variables used via `var(--color-primary)`.
- Ids are prefixed by type: `fr_`, `el_`, `tx_`, `im_`, `sv_`, `pg_`, `doc_`.
- Errors come back as a tool result with `isError` and a text message (see [Errors](#errors)).
- The server sends `instructions` in the handshake (see [Server instructions](#server-instructions)).

## Server instructions

On `initialize`, the server returns short `instructions` for the client to put in the agent's context: what the app is, start with `get_guide('getting-started')` and `get_basic_info`, define the design system (tokens and themes) before drawing, prefer `write_html` (HTML with Tailwind classes is detected; `get_guide('tailwind')`), always check with `get_screenshot`, `docId` is optional, and call `finish_working` when done. The CLI's stdio proxy (`mockup mcp`) forwards these instructions to the client.

## Typical flow

1. `get_basic_info` and `get_guide('getting-started')`: app state and usage rules.
2. `create_document` or `open_document`.
3. `get_guide('tokens')`, `set_tokens` and `create_theme`: define the design system (colors, fonts, spacing, dark theme) before the frames; `get_tokens` to check.
4. `create_frame` and `write_html` to build the content.
5. `get_tree_summary`, `get_styles`, `update_styles`, `set_text`, `set_tag`, `move_nodes`, `set_node_flags`: inspect and adjust. `create_page`, `rename_page` and `delete_page` organize the pages.
6. `save_document` (autosave also saves after 800 ms without edits).
7. `get_screenshot` after each set of changes, fix and repeat (see [Seeing the result](#seeing-the-result)); when done, `finish_working`.

## Tree summary format

One line per node, indented by level: `id "name" tag [dimensions] [layout] [relevant attributes]`.

```
fr_ab12 "Hero" div 1440x800 flex-col gap:24 p:64 bg:#111
  tx_9f3k "Title" h1 "Welcome…" 48px/700
  tx_2m8x "Subtitle" p "Create mockups with AI" 18px/400
  el_7q1c "CTA" button 160x48 bg:var(--color-primary)
```

Abbreviations: `flex-col`/`flex-row` (direction), `gap:`, `p:` (padding), `bg:` (background), `48px/700` (font size/weight). Long text is truncated with `…`. Children beyond the requested depth appear as a count.

### Example: create a frame and content

Call:

```json
{
  "name": "create_frame",
  "arguments": {
    "name": "Hero",
    "width": 1440,
    "height": 800,
    "styles": {
      "display": "flex",
      "flex-direction": "column",
      "gap": "24px",
      "padding": "64px",
      "background": "#111"
    }
  }
}
```

Response (text):

```
Frame created: fr_ab12
fr_ab12 "Hero" div 1440x800 flex-col gap:24 p:64 bg:#111
```

Call:

```json
{
  "name": "write_html",
  "arguments": {
    "parentId": "fr_ab12",
    "html": "<h1 style=\"font-size:48px;font-weight:700;color:#fff\">Welcome</h1><p style=\"color:var(--color-muted)\">Create mockups with AI</p>"
  }
}
```

Response:

```
2 nodes created
fr_ab12 "Hero" div 1440x800 flex-col gap:24 p:64 bg:#111
  tx_9f3k "Title" h1 "Welcome" 48px/700
  tx_2m8x "Text" p "Create mockups with AI" 16px/400
```

## Seeing the result

The agent needs to **see** what it created. The recommended loop (`get_guide('screenshot-loop')`):

1. Create or edit (`write_html`, `update_styles`, `insert_image`...).
2. `get_screenshot(nodeId)` and check: alignment, clipping, overflow, contrast, wrapping text.
3. Fix and repeat step 2.
4. `finish_working` when done, to clear the "AI" indicator in the editor.

Prefer `scale` 1 and `maxWidth` (e.g. 800) to spend less context; `get_layout` gives the exact measurements as numbers.

`get_screenshot` also accepts `time` (number, seconds, from 0): it renders the frame of all animations at that instant (effects, particles, Lottie, Rive, Three.js and video). Without `time`, the render uses 0, and a video with a `poster` shows the poster. Compare `time: 0` and `time: 2` to check the animation. Details in [EFFECTS.md](EFFECTS.md#how-the-render-captures) and [EMBEDS.md](EMBEDS.md#poster-and-screenshot).

**When the render is available:** `get_screenshot`, `get_layout`, `export` png/jpg and the measured SVG depend on the render engine (Electron): in the desktop app or in the headless Electron that `mockup mcp` starts when Electron is installed. On a plain Node daemon these tools return `isError` explaining how to enable it (`export` svg/html/tailwind/react and `get_code` keep working; the SVG uses a fallback without measurements).

```
Invalid parameters in create_frame:
- width: required and missing (expected: number).
- height: wrong type: expected number (number), received text (string) "900px".
Example: create_frame({"name":"Desktop","width":1440,"height":900})
```

Nonexistent tool: `Tool "write_htm" does not exist. Similar tools: write_html, ...`. Errors about ids and state (node not found, no open document, render unavailable) say which tool to use next; `get_guide('troubleshooting')` gathers the solutions.

### Scripts, remix and assistant

| Tool           | Parameters                                                                                                                                             | Description                                                                                                                                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run_script`   | `code` or `name` (script saved in `scripts/`), `timeoutMs`, `docId`                                                                                    | Runs JavaScript with the document API (`doc.select`, `node.style`, `doc.apply`, `doc.screenshot`...) in a sandbox (worker + `node:vm`, no `require`/`process`/`fs`, timeout and memory limit). One run = one undo. Returns logs, result, number of ops, images and summary. Details in [SCRIPTS.md](SCRIPTS.md). |
| `list_scripts` | `docId`                                                                                                                                                | Lists the `scripts/*.js` library next to the document.                                                                                                                                                                                                                                                           |
| `remix`        | `nodeId` (required), `kind` (`color-scale` \| `font-pairs` \| `spacing` \| `layout` \| `ai`, required), `count`, `prompt` (required for `ai`), `docId` | Variations of the node's frame side by side (one undo). The first four are local and deterministic; `ai` runs an assistant turn. Details in [ASSISTANT.md](ASSISTANT.md#remix).                                                                                                                                  |

Sessions opened by the editor's assistant (`/mcp?turn=<token>`) are tied to the turn: all writes go into a single undo group, `undo`/`redo` are rejected during the turn and, after the turn ends, the session no longer writes (see [ASSISTANT.md](ASSISTANT.md)). `run_script` and `remix` called inside a turn go into the same group.
